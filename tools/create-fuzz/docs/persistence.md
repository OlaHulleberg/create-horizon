# Persistence actions and saved observations

Version 3 events accept `{"kind":"reload"}`. This is an area action: its
position participates in the usual scenario region bounds, while every block
entity in that region reloads. The action runs in event-array order after
initial placement and delayed motor settings, before the next world tick.
World block states, scheduled block ticks, player state and external entities
remain in place. There is no simulated offline time.

Java saves all area entities with saveWithoutMetadata(registryAccess) before
removing any. Type identity is added for BlockEntity.loadStatic. Each old entity
receives onChunkUnloaded before removeBlockEntity marks it removed; this runs
SmartBlockEntity's unload/invalidation path without treating it as destruction.
Fresh loadStatic instances enter the level with setBlockEntity and initialize
on their next normal entity tick. Chunk tickets are retained: forced chunks
and the shared level make ticket removal an unsuitable area isolation primitive.
This tests entity persistence, not chunk I/O or server restart durability.

Rust uses the MIT glue codecs over a local typed NBT value tree. The encoded
value tree crosses a byte serialization boundary; engine objects do not survive
by cloning. End-of-tick kinetic changes populate persisted records, and motor
settings/belt inventories populate column attachments. Reload calls
column_unloaded, loads column settings/items/fluid records, scans with block_loaded, restores
handle use with restore_handle before kinetic ports with restore_state, then
loads sequencer instructions/run.
Saved BeltState membership restores immediately after each block_loaded, before
kinetic ports. Every saved kinetic restore is checked; no extra solve or transport
tick is inserted into reload.
Conveyor links use Chains::unload/add and set_far. Host slots and valve-use data
cross the serialization boundary independently of engine state.

Sequencer run records update at instruction transitions and in the glue's
post-subsystem write_entities phase. Java's initial game-time modulo 10 remains
in snapshot save_phase for replay compatibility; it no longer selects periodic
sequencer writes. This is timing metadata, not a compared result. `rust <case.json> [phase]` permits
matching standalone replay (default phase 0). No world clock is reset.

The additive saved records compare kinetic speed/update flag/source position
and network stress/capacity/size/added contributions. Raw network ids are never
emitted. Subsystem payloads compare sequencer instructions/run; valve selected
angle/total use duration/target; belt controller/index/length/casing, persisted
inventory order/stack/position/lock; and depot held slots. Floating fields use
the existing kinetic tolerance. Random render angles and dependent offsets
are excluded symmetrically. Belt save observations project write's committed
queues without mutating the live inventory; the actual reload uses write.

Explicit boundaries:

- Crank and valve HandleState changes are flushed every tick, including
  countdown-only changes, and restored after block_loaded before kinetic ports. InUse and
  Backwards are compared for both, and StartAngle for valves. Cooldown is
  deliberately absent from the codec, matching Java's fresh-entity lifecycle.
- DepotState records persist engine-owned held motion, insertion side, angle,
  offset, lock and fan progress independently of host slot identity/count.
  Records flush every tick, including empty records and movement without client
  notifications. Reload restores them after block_loaded; only missing records
  take the reload-time legacy initialization. The following ordinary depot tick
  still runs the glue's occupied-slot fallback, including #35. Processing
  output/incoming queues remain outside generated inputs.
- BeltState captures Controller/Index/Length for all members of controllers
  notified in the belt phase, including empty inventories. Saved insertion
  segment/direction and empty inventory travel direction survive reload. New
  chains still initialize through the normal belt tick.
- Old drawing-only legacy saves, corrupt saves, actual chunk ticket transitions,
  disk durability, config profiles, unmodelled item components, machine work and
  native item flight are not generated by this action.

Half of generated seeds overlay a reload on an existing scenario family.
Placement, post-action and settled boundaries are sampled; checkpoints cover
the reload boundary and five following ticks. Handwritten reload histories cover
propagation, sequencer/valve/crank use, belt/depot items, wrenching and break
cascades. Original histories remain available in the corresponding ordinary cases.

## Batch network isolation

Each batch starts with a fresh Create kinetic network registry after block/entity
cleanup, through TorquePropagator.onUnloadWorld/onLoadWorld. No active case runs
across this boundary. Reloads inside a case retain the ordinary registry and all
observations remain compared. Create's fresh entities can leave old removed
members in the world registry after an entity reload. Clearing current blocks
alone does not guarantee that these registry objects disappear. Network ids
are positional, so a later case in the same slot can reuse a stale network.
This primitive isolates scenario worlds without changing map iteration,
network algorithms, saved caches or comparison rules. Startup/reset diagnostics
report removed members left after cleanup; instability diagnostics print the
labelled compare::diff(first, rerun) result.

## Persisted records versus a forced fresh serialization

Reload consumes saved records, never current engine getters. Through engine
0fc666f, sequencer progress and late depot handoffs could differ from the glue's
last entity write. Commit 7e33c30 adds Subsystem::write_entities after every
subsystem tick and before column flush. The driver mirrors that real publisher:
depots first and sequencer runs second, with no added unload-time operation.
Kinetic/handle journals and marked column attachments retain their own write
points. The earlier write-phase commit and #35 regression preserve the unfixed
behavior in history; with the port publisher present, #35 should match Java.
#34 is independently checked by live registry size two versus cached size one.

## Save record scheduling

The adapter captures each record at its owning glue write point. A late flush
must not refresh an earlier entity record or serialize an unmarked column.

| Record | Capture point |
|---|---|
| DepotState | Post-subsystem write_entities, every registered depot including empty records, after all transfers |
| BeltState | Belt-phase changed-controller notifications, all chain members; inventory column data stays at its marked end-of-level flush |
| HandleState | After solve, sequencer steps and world effects; only take_handle_changes |
| Kinetic ports | Same solve phase, after handles; only take_saved_changes, excluding pending legacy migration |
| Adjustable chain Signal | Same saved-change journal, after kinetic ports; saved_chain_signal reads the entity value, including analog changes without a speed change |
| Sequencer run | Actual instruction transitions plus post-subsystem write_entities; save_run writes only its five run fields |
| Sequencer instructions | Immediately in an accepted program message, independently of run saves |
| Motor settings and belt inventories | End-of-level persist::flush, only marked columns; collect engine unsaved columns at the solve's actual drain point |
| Fluid tank/plumbing/machine/open-end column records | Same marked column flush, using glue/fluids codecs; an empty replacement removes stale fluid records |
| Tank entity Tank/Tank_fluids | fluids::Tanks changed-position journal after logistics/tools/arms and before Solve, including empty data for former controllers |
| Brackets and conveyor topology | Same marked column flush; bracket mutations and the packages changed/gone journal mark their columns |
| Host slots, belt casing and valve selection/use metadata | Their existing immediate host writes; reload round-trips those host records without refreshing engine state |

Belt inventory motion and direction changes enqueue belt_changes during the
logistics phase, then mark their controller columns. A chain formed later by
settle_belts is not spuriously captured before its later change notification.
Kinetic callbacks occurring after take_unsaved remain pending until the next
solve, matching the glue. Reload consumes the saved records as they stand.

The #35 regression is cases/persistence-depot-belt-save-order.json. Before
7e33c30, the completed-tick-90 handoff left an empty saved depot record; reload
then produced position 0.5 instead of Java's 0.125. The new port publisher saves
the handoff before reload. The driver follows this changed source phase rather
than filtering the comparison or forcing a fresh unload-time serialization.

These scenarios observe the completed-tick publication boundary. They do not
establish parity for host saves/unloads occurring earlier in the level tick or
for mutations made by other mods afterward. The port still documents a missing
before-entity-save callback in API_GAPS.md; no unload-time refresh can repair an
already saved chunk. The driver does not invent such a callback.

Reload completes each kinetic block_entity_on_load callback before starting the
next entity: block_loaded, saved belt/depot/handle fields, kinetic ports, then
that entity's sequencer instructions/run. It does not restore all entities'
kinetic ports first and defer all sequencer callbacks to a later pass. The
sequencer reload fixture compares this path with an independent per-entity
reference using the same public engine entries. Publication remains unchanged.

With the chain signal load API, every entity callback first calls
restore_chain_signal after block_loaded and before the belt/depot/handle/kinetic
restores. Missing or mistyped Signal defaults to zero, as ChainGearshiftBlockEntity.read
does. The input signal is not polled to rebuild the save.
Freshly constructed chain entities receive the same missing-Signal zero read
before their first attachment; in-place state changes retain their entity value.
The chain modifier
observation reads the engine's entity value rather than a separate input cache.
Pending chain shapes use the same property commits during Inputs and immediately
after each kinetic break, matching the glue's synchronous neighbour updates.

Fluid columns stage `tank_multis` (and legacy `tanks`) through `load_tanks`
before any block is scanned. The controller's saved fluid, amount, width, height
and window flag therefore exist when `block_loaded` calls `Tanks::load`.
The entity's `Tank` drawing record crosses the encoding boundary too, but the
glue's `KineticEntity::block_entity_on_load` does not read it as authoritative
fluid state. A newer drawing record must not refresh an older column attachment.
No fluid getter is called to refresh the save at the reload boundary.

The fluid codecs also retain the glue's `create_fluids` filter items/fluids,
quantized hose offsets/tanks, creative tank fluids/sizes, `create_machines`
spout/drain tanks and held drain items, and open-end tanks/pulling flags.
They load before entity scans, in the glue's tank/plumbing/machine/pipe order.
Pump routes/flows follow the glue's ordinary fresh-load path. Fluid-valve pointer records use the owning entity's Pointer Value/Target/Speed codec and restore before attachment. In particular, spout processing is not in its column codec,
while a drain's processing counter is. Round-trip fixtures exercise these
distinctions. The fluid driver also supplies contained native-world callbacks and
a startup-audited component-free recipe subset; remaining boundaries are listed in `fluids.json`. Tank reload histories cover controller removal, changed windows,
repeated loads and per-tick checkpoints; filled and cross-column records also
have Rust-only regressions.

# Create for Horizon, v2: a trait mod on current Horizon

The working port (`stable/9d979ca`) is a horizon-mixins bundle on Horizon 9d979ca with our own hook
branch (API 41–67). Horizon has moved on: native mod API work now happens on
[arismoko/horizon](https://github.com/arismoko/horizon) (trackers #26–#29), the API is the typed
`horizon_client::mod_api` (`Hooks`, `Host`, typed handles, attachments), and the stated goal is that "the
most popular complex mods never need mixins" (horizon-rust/horizon#7386, Ari). Create is the reference mod
in #7386 and #7387. v2 follows that direction; `stable/9d979ca` stays untouched as the working version.

## Shape

- **A trait mod first.** `mixins/create/horizon-mixin.toml` gets an `[api]` package (`docs/native-mods.md`,
  "Trait mods"). It holds the engine (`create-engine`, pure Rust) and all of Create's logic, implementing
  `Hooks` with catalog hooks and reaching the game through `Host` and its handles (`EntityRef`, `LevelRef`,
  …). Per-world state lives in attachments; shared state behind interior mutability.
- **A small mixin part only for gaps.** Where no catalog hook or handle exists yet, a trait injection
  (`trait_method`) or a thin helper that hands off to `dyn Host` or an attachment. Every such injection
  names the gap it covers and the request filed for it, so the mixin part shrinks as hooks land.
- **Main's hooks, not ours.** Where main already has the hook we had added (chunk load/unload, level
  load, analog output, entity inside, interaction keys, entity mount, extract item, input key), v2 uses
  main's and drops ours. Saved data moves to attachments.
- **Hot paths stay in the engine.** Kinetic networks, block entities, belts and contraptions are solved in
  batches inside the engine and reach the game through a few hook calls, not one `Host` call per block.
- **Horizon changes only for real gaps.** `feat/create-hooks-v2` on
  [OlaHulleberg/horizon](https://github.com/OlaHulleberg/horizon), branched from current main: one small
  commit per gap in main's conventions (a `tools/native-hook-fragments` entry, a `mod_api` contract, no cost
  with no mod loaded, handle methods rather than ID helpers). Engine-side pieces (instanced parts #6302,
  per-position models #6303, content `render_shape` and occlusion #5550, mod fluids #6301) are kept as
  separate commits there for the people who own those designs to look at, not as proposals.

## Order

1. Static content and kinetics (shafts, cogs, motors, gauges, stress) as a trait mod, proven in game and
   benchmarked against the 9d979ca numbers in PORTING.md.
2. Processing, logistics and redstone.
3. Fluids and equipment (containers wait on capability parts upstream; carried as gaps until then).
4. Contraptions and trains.

Each step: all checks green, an in-game proof, a benchmark within the PORTING.md budgets, and the Create
coverage ledger (what each Create need maps to upstream) kept current.
